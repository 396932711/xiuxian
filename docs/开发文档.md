# 《宗门》开发文档

> 本文档为**技术开发与版本计划**文档。游戏玩法设计见 [设计文档.md](./设计文档.md)；**版本开发计划以本文档为准**。

## 一、版本开发计划

### v1.0 · 阶段1最小可玩原型（已确认，待开发）

**目标**：做出最核心的"建宗门+收灵石"循环，孩子能直观看到成果。

**实现功能**：

1. **资源**：仅灵石 1 种
2. **建筑（3 个）**：宗门大殿（核心）/ 灵矿场（生产）/ 招募堂（功能）
3. **弟子**：招募、分配至灵矿场采集、练气境界 1-10 级、修炼升级、状态（空闲/采集中，召回无损）
4. **自动产出与离线**：矿场自动产灵石 + 离线收益 2 小时上限
5. **UI**：主界面（顶部资源栏 + 建筑场景 + 底部导航）、建筑升级弹窗、招募界面、弟子界面
6. **持久化**：localStorage 本地存档

**明确不含**：筑基突破、药田/丹房/藏经阁、日常任务、弟子天赋、战斗/秘境、装备。

**验收标准**：孩子能在 3 分钟内完成"招募1名弟子 → 分配至灵矿场 → 看到灵石增长 → 升级一次矿场/大殿"的完整闭环，并能离线后回来看见收益。

## 二、技术选型

### v1.0 选型：单文件 HTML + 原生 JS + localStorage

**理由**：

* 无构建步骤，孩子双击 `index.html` 即可在浏览器打开

* 迭代快，适合亲子边做边试

* localStorage 满足单机存档需求，无需后端

**技术栈**：HTML / CSS / 原生 JS (ES6+)，**v1.0 不引入任何框架与依赖**。

### 后续版本迁移路径

* **v1.1**：仍可单文件，按需把 CSS/JS 拆出为独立文件

* **v1.2+**：若复杂度上升，迁移至 Vite + 原生 ES 模块化（仍不引入框架，保持孩子可读）

* **战斗/动画密集时**再评估是否引入轻量渲染库

## 五、数据模型

### 存档结构（save）

```js
{
  version: "1.0",
  lastSaveTime: 1690000000000,   // 离线结算基准时间戳
  sect: { name: "无名宗门" },
  resources: { lingshi: 0 },
  buildings: {
    dian:   { level: 1 },                    // 宗门大殿
    kuang:  { level: 1, workerIds: [] },     // 灵矿场（分配中的弟子id）
    zhaomu: { level: 1, refreshCdEnd: 0 }    // 招募堂（刷新CD结束时间戳）
  },
  disciples: [
    {
      id: "d_1",
      name: "张道凡",          // 可改名；招募时由名字库随机组合生成
      realm: "练气",
      level: 1,
      exp: 0,
      status: "idle",        // idle | mining
      assignTo: null,        // null | "kuang"
      base: { root: 1.0 }   // 根骨倍率（v1.0 暂不引入天赋，预留字段）
    }
  ],
  nextDiscipleId: 2
}
```

### 解锁与依赖规则

* 其他建筑等级上限：`otherLevelMax = dian.level`（大殿等级）

* 弟子数量上限：`discipleCap = 2 + dian.level`

* 灵矿场工位上限：`kuangCap = 1 + kuang.level`

### 名字库与改名（v1.0 已确认）

**结论**：弟子名字采用**内置国风名字库随机组合** + **支持玩家自定义改名**。

**名字库（Config 常量，不入存档）**：

```js
const NAME_LIB = {
  surnames: ["张","王","李","赵","陈","林","周","沈","顾","苏",
             "萧","楚","凌","叶","秦","墨","白","云","风","陆"],
  given:    ["道凡","清风","明月","云鹤","青衣","子期","长歌","无尘","若虚","观山",
             "听雨","辞树","归尘","忘机","问渠","知秋","望舒","星河","怀瑾","漱石"]
};
// 招募时随机组合：name = random(surnames) + random(given)，如"凌忘机"
```

**改名机制**：

* 弟子详情页名字旁提供"改名"按钮（或直接点击名字进入编辑）
* 弹出输入框，输入新名字（限制 **1-6 个字符**），确认后写入 `save.disciples[i].name`
* 名字字段在存档 schema 中为字符串，招募时初始值来自名字库随机组合，后续可被玩家覆盖
* 名字库作为 Config 常量，方便后续让孩子参与扩充（亲子参与设计点）

## 六、核心循环设计

### tick 机制

* `setInterval(render, 1000)`：每 1 秒刷新 UI（资源数、倒计时）

* `setInterval(produce, 10000)`：每 10 秒结算一次产出与经验

### 产出结算（每 10 秒）

```js
// 伪代码：矿场在岗弟子产出灵石
for (const id of buildings.kuang.workerIds) {
  const d = disciples.find(x => x.id === id);
  const gain = 1.5 * (1 + 0.1 * (d.level - 1)) * d.base.root; // 灵石/10s
  resources.lingshi += gain;
}
```

### 修炼结算（每 10 秒）

* 闲置弟子自动缓慢获经验：`exp += 1`（满级 10 级后不再增长）

* 在岗弟子也可获经验（便于孩子不操作也能成长）

### 离线收益（进入游戏时一次性结算）

```js
const offlineSec = Math.min(Date.now() - save.lastSaveTime, 7200); // 封顶2小时
const ticks = Math.floor(offlineSec / 10);
let gain = 0;
for (const id of buildings.kuang.workerIds) {
  const d = disciples.find(x => x.id === id);
  gain += 1.5 * (1 + 0.1 * (d.level - 1)) * d.base.root * ticks;
}
resources.lingshi += gain;
// 弹窗："离线 X 分钟，收获灵石 ×gain"
```

## 七、数值公式落地（v1.0）

| 项          | 公式                                    | 示例                      |
| ---------- | ------------------------------------- | ----------------------- |
| 弟子产出 /10s  | `1.5 × (1 + 0.1×(lv-1)) × root`       | 1级=1.5，10级=2.85         |
| 建筑升级消耗（灵石） | `100 × 1.3^(lv-1)`                    | 1→2=100，2→3=130，3→4=169 |
| 弟子升级所需经验   | `100 × 1.3^(lv-1)`                    | 1→2=100，2→3=130         |
| 弟子数量上限     | `2 + dian.level`                      | 大殿1级=3                  |
| 矿场工位上限     | `1 + kuang.level`                     | 矿场1级=2                  |
| 招募单次消耗     | `50` 灵石（默认，可调）                        | —                       |
| 招募刷新CD     | `max(30 × 0.9^(zhaomu.level-1), 5)` 秒 | 1级=30s                  |

> 标注"默认/可调"的数值对应设计文档"待确认事项"，v1.0 先用默认值落地，试玩后调整。

## 八、UI 交互流程（v1.0）

### 主界面布局

* **顶部栏**：宗门名 + 等级 ｜ 灵石数（图标+数字）

* **中部**：3 个建筑卡片（大殿/矿场/招募堂），点击 → 弹出管理面板

* **底部导航**：弟子按钮 → 弹出弟子列表抽屉

### 建筑管理面板

* **宗门大殿**：当前等级 / 弟子上限 / 下一级解锁说明 + 升级按钮（灵石不足置灰）

* **灵矿场**：工位占用 X/Y + 升级按钮 + "分配弟子"入口

* **招募堂**：招募按钮 + 单次消耗 + 刷新倒计时

### 弟子列表与详情

* 列表每条：头像 + 名字 + 境界等级 + 状态标签

* 点击弟子 → 详情：属性 + "改名" + "分配至矿场" / "召回" 按钮

### 招募结果反馈

* 弹出弟子卡片 + 简单 CSS 光效动画

## 九、v1.0 开发里程碑（任务拆解）

按顺序实现，每步可独立验证后再进入下一步：

1. **骨架与存档** — `index.html` 空壳 + Save/Load + 离线结算骨架
2. **资源与主循环** — 灵石显示 + 每 10 秒自增（测试期可无弟子也产基础值）
3. **宗门大殿** — 升级 + 消耗公式 + 弟子上限联动
4. **弟子与招募堂** — 招募（名字库随机命名）+ 弟子列表 + 状态字段 + 改名功能
5. **灵矿场分配** — 分配/召回（召回无损）+ 矿场产出结算
6. **弟子修炼升级** — 经验积累 + 升级 + 产出系数提升
7. **离线收益弹窗** — 进入结算 + 收获提示
8. **数值调优与试玩** — 验证 3 分钟闭环验收标准
