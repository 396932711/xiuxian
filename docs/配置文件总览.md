# 宗门游戏 · 配置文件总览（v1.3.1 新增存档导入导出/重置）

> **目标**：让孩子/家长不碰代码、只改 JSON 就能调整游戏体验。
> **修改步骤**：编辑对应 `.json` → 保存 → 刷新浏览器页面立即生效。
> **加载规则**：
> - 通过 HTTP 打开（如 `http://localhost:8000/index.html` 或部署到 GitHub Pages）时，程序会 `fetch` 这 6 份 JSON；
> - 若本地双击 `file:///...` 导致 CORS 失败、或某个 JSON 读不到 / 字段错，程序会**自动回退到 `assets/config.js` 里内嵌的默认值**（保证不卡、不崩），并在 F12 控制台打印 `usedFallback: true` + 错误原因。
>
> **v1.3.1 更新**：底部导航「弟子/建筑/背包/任务/设置」改为由 `ui.json` 的 `uiText.bottomNav` 数组驱动（设置为存档管理入口）；新增 `values.saveFile.*` 控制导出存档文件名前缀和重置确认词；新增 `uiText.saveMgr* / import* / reset*` 一整套设置弹窗文案。

## 一、values.json（数值常量）

| 字段 | 类型 | 含义 |
|---|---|---|
| `tickSeconds` | number | 一个产出 tick 的秒数（默认 10 秒，改更小=收益更快） |
| `idleExpPerTick` | number | 每个 tick 给全员（含掌门）的经验 |
| `maxLevelPerRealm` | number | 每个大境界的最高等级（阶段1 10级） |
| `initLingshi` | number | 新游戏初始灵石数 |
| `offlineCapSeconds` | number | 离线收益累计上限（秒），默认 7200 = 2 小时 |
| `storageKey` | string | 浏览器 localStorage 存档键名，改了等于重置进度 |
| `produce.basePer10s` | number | 练气1级弟子基础产出（灵石/10s）|
| `produce.perLevelMul` | number | 每升1级，产出增加多少倍（0.1 = 每级 +10%）|
| `upgrade.baseCost` | number | Lv.1 → Lv.2 的灵石 |
| `upgrade.growthMul` | number | 每升一级，升级消耗乘多少（1.3 = 每级 +30%）|
| `exp.baseNeed` | number | Lv.1 → Lv.2 的经验 |
| `exp.growthMul` | number | 每升一级，经验需求乘多少 |
| `discipleCapFormula.type` / `base` / `perDianLevel` | string/num | 弟子上限 = `base + perDianLevel × 大殿等级`，默认 2 + 1×L |
| `avatar.compress.rawFileMaxKB` | number | 原始图片文件大小上限（KB），默认 8192 = 8MB |
| `avatar.compress.dataUrlMaxKB` | number | 压缩后 DataURL 字节上限（KB），默认 256KB（保证 localStorage 不炸）|
| `avatar.compress.maxSide` / `fallbackSide` | number | 压缩图最大边长，默认 512；最终兜底缩 256 |
| `avatar.compress.qualitySteps[]` / `fallbackQuality` | number[]/num | JPEG 质量阶梯 0.82→0.6→0.4→0.25，最终兜底 0.2 |
| `leader.root` | number | 掌门根骨（优级）= 1.2，影响产出和修炼 |
| `leader.produceMul` | number | 掌门亲自打工时的额外产出倍率（×1.5） |
| `leader.moraleMul` | number | 掌门在岗，全员士气加成（1.1 = +10%）|
| `leader.defaultName` / `defaultAvatarImg` | string | 新游戏掌门初始姓名 + 默认头像路径 |
| `recruit.cost` | number | 单次招募消耗灵石 |
| `recruit.cdBaseSeconds` | number | 招募堂 Lv.1 冷却（秒） |
| `recruit.cdGrowthPerLevel` | number | 每升级招募堂，冷却乘多少（0.9 = 每级 -10%） |
| `recruit.cdMinSeconds` | number | 冷却下限（秒） |
| `saveFile.exportNamePrefix` | string | 「设置→导出存档」时自动生成的文件名前缀，默认 `宗门-存档`；完整文件名 = `{prefix}-{宗门名}-{掌门名}-{年月日}-{时分}.json` |
| `saveFile.confirmResetWord` | string | 「设置→重置存档」时要求输入的确认词；防孩子/大人误点清空进度。默认 `重置`。想更严格可改成 `确认重开宗门` |

**数值实验示例**：
- 想让孩子 1 分钟内就能升级：`produce.basePer10s` 调到 `3`、`upgrade.baseCost` 改成 `60`。
- 想让离线收益有 4 小时满足感：`offlineCapSeconds` 改成 `14400`。

## 二、buildings.json（建筑定义）

```json
{
  "order": ["dian", "kuang", "zhaomu"],   // 渲染顺序（从左到右）
  "buildingMeta": {
    "dian": {
      "id": "dian", "name": "宗门大殿", "img": "路径", "desc": "...",
      "isCore": true,
      "capRules": {
        "discipleCap": { "type": "linear", "base": 2, "perLevel": 1 }
      }
    },
    "kuang": {
      "id":"kuang", "name":"灵矿场", "img":"...", "desc":"...",
      "workerType":"mining",
      "slotCap":   { "type":"linear", "base":1, "perLevel":1 },
      "produces":  ["lingshi"]
    },
    "zhaomu": { "id":"zhaomu", "name":"招募堂", ... }
  }
}
```

**改法**：
- 想改大殿弟子上限更快：`dian.capRules.discipleCap.perLevel` 改 `2`（每升大殿 +2 名弟子）。
- 想改矿场初始工位：`kuang.slotCap.base` 改 `2`（初始 2 工位，不用等升级）。
- **阶段2新增药田**：在 `order` 追加 `"yaotian"`，并在 `buildingMeta` 里加上对应条目——代码会按表自动渲染卡片；但逻辑（种植灵药）仍需对应写新模块，这里只管元数据。

## 七、常见问题

### Q1：改了 JSON 刷新页面没效果？
1. 按 F12 控制台看 `[宗门] 配置加载完成`，如果 `usedFallback: true`，说明 HTTP 方式不对，改用本地服务器（`python3 -m http.server`）访问，或直接看返回的错误原因（`fetch CORS / 404 / JSON parse error`）。
2. 检查 JSON 语法：有没有漏逗号 / 多逗号 / 中文引号。可以把 JSON 粘到 https://jsonlint.com 先验证。

### Q2：想测试极端数值但又怕影响孩子正常存档？
- 改 `values.storageKey` 为 `"zongmen_save_v1_debug"` 即可把调试用存档和孩子正式存档分开；试完改回原 key。
- 也可直接用 **设置 → 导出** 先把孩子进度存好再折腾，出问题 **设置 → 导入** 恢复即可。

### Q3：新增了建筑 key 但代码不认识 workerType？
- `buildings.json` 只管元数据与卡片渲染。**工位/生产逻辑**还需要在 `index.html`（对应 `kuangCap`、`assignToKuang`、`tick()` 等函数）补充相应分支，建议跟开发文档的里程碑同步新增。

### Q4：F12 控制台能临时改数值吗？
能。在控制台改：
```js
GameConfig.values.produce.basePer10s = 3;   // 下一个 tick 就按新值算
```
这是"本页面本次会话"的临时效果，刷新就失效。正式改还是写回对应 JSON。

### Q5：孩子的存档想复制到爸爸电脑/另一台浏览器上继续玩？
1. 孩子电脑：进入游戏 → 底部 **设置 → 📦 导出存档为 JSON 文件** → 得到 `宗门-存档-XX宗门-小掌门-YYYYMMDD-HHMM.json`。
2. 把文件拷到爸爸电脑（发微信/邮件/U 盘都行）。
3. 爸爸电脑：进入同一个《宗门》页面 → 底部 **设置 → 📥 从 JSON 文件导入存档** → 选刚才的文件 → 提示导入成功后自动刷新，进度无缝接续。
> 注意：两台机器如果用了不同的 `values.storageKey`，导入会写到当前浏览器当前 key 下（一般孩子和家长都用默认 `zongmen_save_v1`，无需额外调整）。

### Q6：孩子误点想"重开新档"？
- 现在提供的是**带二次确认 + 文字验证**的重置流程：底部 **设置 → 🔄 重置存档** → 会强制要求输入 `values.saveFile.confirmResetWord`（默认「重置」）两个字。
- 家长若担心孩子能认出「重置」，可把 `confirmResetWord` 改成更隐蔽的句子（如 "和爸爸一起重建宗门"），这样孩子单点点不掉。
- 正式重置前，建议先让家人都点一下 **导出** 做个备份存档，避免误操作后无回退。

### Q7：导出的 JSON 文件能不能自己用记事本改再导入？
可以。文件结构很直观：
```json
{
  "__zongmen_save__": true,
  "meta": { "_exportedAt": "ISO时间", "_storageKey": "zongmen_save_v1", "_version": "1.2" },
  "data": { /* 跟 localStorage 里一模一样的 state */ }
}
```
想把灵石改成 99999：打开 JSON → 搜 `"lingshi"` → 改 `data.resources.lingshi = 99999` → 保存 → 回到游戏 **设置 → 📥 导入** 即可。推荐改之前先复制一份，改错了导入时如果校验不通过会提示"不是有效的宗门存档"。

## 八、开发者：ConfigLoader 的契约

`assets/config.js` 对外暴露 `window.GameConfigLoader`：

```
GameConfigLoader.loadAll()                  -> Promise<{cfg, sourceMap, warnings, usedFallback}>
GameConfigLoader.validate(cfg)              -> warnings[]（缺字段会回填默认值并收集告警）
GameConfigLoader.injectThemeColors(colors)  -> 注入 CSS 变量 --qing/--wood/--gold/--ink/--cloud
GameConfigLoader.helpers(cfg)               -> H：producePer10s / upgradeCost / expNeeded / discipleCap / slotCap / recruitCdSec / moraleMul / genName / maxLevel
```

业务代码（index.html 等）不应再硬编码任何常量，全部走 `GameConfig.*` 和 `H.*`。新增模块时，把新 JSON 加入 `loadAll()` 的 6 元映射表 + 新增 validate 的对应字段分支即可。
