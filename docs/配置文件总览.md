# 宗门游戏 · 配置文件总览（v1.4 UI 精修：布局 tokens + 建筑坐标化 + 底栏/顶栏瘦身）

> **目标**：让孩子/家长不碰代码、只改 JSON 就能调整游戏体验，连**"建筑摆在背景图什么位置、大小多少、标签在图的哪一侧、底部导航要多高多细"**这种纯 UI 细节也能 JSON 里直接调。
> **修改步骤**：编辑对应 `.json` → 保存 → 刷新浏览器页面立即生效。
> **加载规则**：
> - 通过 HTTP 打开（如 `http://localhost:8000/index.html` 或部署到 GitHub Pages）时，程序会 `fetch` 这 6 份 JSON；
> - 若本地双击 `file:///...` 导致 CORS 失败、或某个 JSON 读不到 / 字段错，程序会**自动回退到 `assets/config.js` 里内嵌的默认值**（保证不卡、不崩），并在 F12 控制台打印 `usedFallback: true` + 错误原因。
>
> **版本更新速查**：
> - v1.3：6 份 JSON 配置外置化；
> - v1.3.1：新增「设置」与存档导入/导出/重置（values.saveFile + uiText 相关文案）；
> - **v1.4 UI 精修**：ui.json 新增 `layoutTokens` 一整组全局尺寸 tokens（顶栏、底栏、建筑、弹窗、按钮等全部可调）；buildings.json 每栋建筑新增 `position / labelPosition / zIndex / cardStyle` 四项，可把每栋建筑"卡"到场景背景图对应的具体位置，而不再是一排居中大卡片。

## 一、values.json（数值常量）

| 字段 | 类型 | 含义 |
|---|---|---|
| `tickSeconds` | number | 一个产出 tick 的秒数（默认 10 秒，改更小=收益更快） |
| `idleExpPerTick` | number | 每个 tick 给全员（含掌门）的经验 |
| `maxLevelPerRealm` | number | 每个大境界的最高等级（阶段1 10级） |
| `initLingshi` | number | 新游戏初始灵石数 |
| `offlineCapSeconds` | number | 离线收益累计上限（秒），默认 7200 = 2 小时 |
| `storageKey` | string | 浏览器 localStorage 存档键名，改了等于重置进度 |
| `produce.basePer10s` | number | 练气1级弟子基础产出（灵石/10s）|
| `produce.perLevelMul` | number | 每升1级，产出增加多少倍（0.1 = 每级 +10%）|
| `upgrade.baseCost` | number | Lv.1 → Lv.2 的灵石 |
| `upgrade.growthMul` | number | 每升一级，升级消耗乘多少（1.3 = 每级 +30%）|
| `exp.baseNeed` | number | Lv.1 → Lv.2 的经验 |
| `exp.growthMul` | number | 每升一级，经验需求乘多少 |
| `discipleCapFormula.type` / `base` / `perDianLevel` | string/num | 弟子上限 = `base + perDianLevel × 大殿等级`，默认 2 + 1×L |
| `avatar.compress.rawFileMaxKB` | number | 原始图片文件大小上限（KB），默认 8192 = 8MB |
| `avatar.compress.dataUrlMaxKB` | number | 压缩后 DataURL 字节上限（KB），默认 256KB（保证 localStorage 不炸）|
| `avatar.compress.maxSide` / `fallbackSide` | number | 压缩图最大边长，默认 512；最终兜底缩 256 |
| `avatar.compress.qualitySteps[]` / `fallbackQuality` | number[]/num | JPEG 质量阶梯 0.82→0.6→0.4→0.25，最终兜底 0.2 |
| `leader.root` | number | 掌门根骨（优级）= 1.2，影响产出和修炼 |
| `leader.produceMul` | number | 掌门亲自打工时的额外产出倍率（×1.5） |
| `leader.moraleMul` | number | 掌门在岗，全员士气加成（1.1 = +10%）|
| `leader.defaultName` / `defaultAvatarImg` | string | 新游戏掌门初始姓名 + 默认头像路径 |
| `recruit.cost` | number | 单次招募消耗灵石 |
| `recruit.cdBaseSeconds` | number | 招募堂 Lv.1 冷却（秒） |
| `recruit.cdGrowthPerLevel` | number | 每升级招募堂，冷却乘多少（0.9 = 每级 -10%） |
| `recruit.cdMinSeconds` | number | 冷却下限（秒） |
| `saveFile.exportNamePrefix` | string | 「设置→导出存档」时自动生成的文件名前缀，默认 `宗门-存档`；完整文件名 = `{prefix}-{宗门名}-{掌门名}-{年月日}-{时分}.json` |
| `saveFile.confirmResetWord` | string | 「设置→重置存档」时要求输入的确认词；防孩子/大人误点清空进度。默认 `重置`。想更严格可改成 `确认重开宗门` |

**数值实验示例**：
- 想让孩子 1 分钟内就能升级：`produce.basePer10s` 调到 `3`、`upgrade.baseCost` 改成 `60`。
- 想让离线收益有 4 小时满足感：`offlineCapSeconds` 改成 `14400`。

### 📌 produce.lingyaoPerMul（灵药产量倍率，阶段 2）
灵药每 tick 的产量 = 灵石公式 × 这个倍率。孩子嫌药田长得慢就加倍（=2）；嫌太快就降到 0.5。

### 📌 alchemy（炼丹配方，阶段 2）
- `recipePillPerBatch`：每个炼丹弟子每 tick 产几颗丹药（默认 1）。
- `recipeLingyaoCostPerBatch`：产 1 批丹药要吃多少株灵药（默认 3）。想让孩子轻松出丹就改成 2。

> 进阶：如果只给**丹房这栋建筑单独改配方**（不和其它建筑混用），直接在 buildings.json 的 `buildingMeta.danfang.recipePillPerBatch / recipeLingyaoCostPerBatch` 两个字段里改（优先级比 values.json.alchemy 高），用来做"以后加丹房分类型"的准备。

### 📌 breakthrough（境界突破调参，阶段 2）
- `pillBoostPerAdd`：多吃 1 颗丹药额外增加的成功率（默认 0.1 = 10%）。
- `pillBoostAddMax`：最多允许额外吃几颗的上限（默认 2，所以基础 80% → 顶多加 2×10% = 100%）。
- `failBackLevelOffset`：突破失败时等级小退的级数（默认 1 = 温柔惩罚，练气 10 → 9；调成 0 = 失败不降级）。

> 想完全免失败就调 `realms.realms.lianqi.breakthrough.baseSuccessRate = 1`。

### 📌 cangjing（藏经阁修炼加成，阶段 2）
- `expBoostPerLevel`：藏经阁每升 1 级，全员（掌门 + 所有弟子，无论在岗/空闲）每 tick 经验乘 `(1 + (Lv-1) × expBoostPerLevel)`。默认 0.05 = Lv.2 起 +5%、Lv.3 +10%。升级到大殿满级给 45% 上限。

### 📌 quests.dailyPool（每日任务池，阶段 2）
`dailyPool` 是数组，里面每条任务对象字段：

| 字段 | 含义 |
|---|---|
| `id` | 唯一 id，不同任务不同（推荐 `q_xxx` 前缀） |
| `type` | `collect_resource`（收集某资源）/ `upgrade_building`（升级建筑次数）/ `exp_sum`（累计经验）/ `recruit_count`（招募数） |
| `resource` | 仅 `collect_resource` 类型需要："lingshi" / "lingyao" / "danyao" |
| `need` | 完成阈值：比如 `collect_resource → need=300` = 收集 300 个指定资源即完成 |
| `reward` | 奖励对象，key 必须是 resources.order（lingshi/lingyao/danyao/contribution）里的资源 id |

`dailyCount`：每天随机从池子里选几条（默认 3，推荐 2~5 之间，孩子别太累）。

### 📐 position（坐标 & 大小，百分比 0~100）—— 把建筑对齐场景背景图的关键！

| 字段 | 含义 |
|---|---|
| `x` | 建筑卡片**中心点**在场景区 #scene 的水平百分比。x=0 贴左、x=50 正中、x=100 贴右。|
| `y` | 建筑卡片**中心点**在场景区的垂直百分比。y=0 贴顶、y=50 正中、y=100 贴底。|
| `w` | 卡片宽度占场景宽度的百分比。大殿一般 24 左右，小堂口 15 左右。|
| `h` | 卡片高度占场景高度的百分比。大殿一般 30~38，小堂口 20~26。|

**调参小技巧（孩子也会玩）**：
- 游戏内打开 **设置 → 🎯 建筑位置快速调参模板** → 「📋 复制整块到剪贴板」。
- 把坐标块粘进 buildings.json 的对应建筑块里，先保存一份原样备份。
- 大殿：想让它"落在中轴远景山上"→ x≈50、y≈20~30；矿场靠山 → x≈20~30、y≈55~70；招募堂门口 → x≈70~80、y≈55~75。
- 卡片过大太突兀？把 w 从 24 → 14，h 从 38 → 22，立刻变小紧凑。

### 🏷️ labelPosition（标签方位）

场景背景图可能在建筑下方是"石阶"、右侧是"竹林"、左侧是"门匾位置"。用 `labelPosition` 把「建筑名 + Lv + 工位」标签挪到空的一侧：

| 值 | 效果 | 适合场景 |
|---|---|---|
| `bottom`（默认） | 图在上、文字在下方居中 | 通用 |
| `top` | 文字在上方、图在下 | 背景图建筑下方有杂物但上方留白多 |
| `left` | 图占右、文字竖排浮在图的左侧（右对齐） | 建筑卡片占了门口右侧大片，左侧门口石墩是空的 |
| `right` | 图占左、文字浮在右侧（左对齐） | 图是靠山面，右侧有空地 |

### 🎨 cardStyle（单建筑外观微调，直接写 CSS）

支持任意 CSS 属性（camelCase 或 kebab-case 都行，数字如果没带单位会自动补 px，例外是 `zIndex / order / flexGrow` 这几个纯数字）。例：

```json
"cardStyle": {
  "background": "rgba(255,249,225,.9)",
  "border": "2px dashed #E8B84E",
  "borderRadius": "16px",
  "filter": "drop-shadow(0 4px 10px rgba(0,0,0,.15))",
  "opacity": 0.95
}
```

### 旧的 flex 居中布局仍可一键切回（兜底兼容）

如果暂时不想管坐标，改 `ui.json.layoutTokens.building_mode = "flex"`，就会回到老的「居中 flex 平铺」模式，`position` 字段失效，所有建筑卡片大小一致排成一排。

**改法**：
- 想改大殿弟子上限更快：`dian.capRules.discipleCap.perLevel` 改 `2`（每升大殿 +2 名弟子）。
- 想改矿场初始工位：`kuang.slotCap.base` 改 `2`（初始 2 工位，不用等升级）。
- 想把矿场卡片缩小放到"山脚下靠左边"→ 改 `kuang.position = {x:20, y:72, w:14, h:22}`，`labelPosition = "right"`（右侧写名字挡住空地）。
- **阶段2新增药田**：在 `order` 追加 `"yaotian"`，并在 `buildingMeta` 里加上对应条目（别忘了给 position，不写默认居中）——代码会按表自动渲染卡片；但逻辑（种植灵药）仍需对应写新模块，这里只管元数据。
- yaotian/danfang/cangjing 三栋为阶段 2 新增，大殿升到 Lv.2 自动解锁（顶栏资源"灵药/丹药"同时显示），孩子想让新建筑出现在场景对应位置只要调 `position.x/y/w/h`。

## 七、常见问题

### Q1：改了 JSON 刷新页面没效果？
1. 按 F12 控制台看 `[宗门] 配置加载完成`，如果 `usedFallback: true`，说明 HTTP 方式不对，改用本地服务器（`python3 -m http.server`）访问，或直接看返回的错误原因（`fetch CORS / 404 / JSON parse error`）。
2. 检查 JSON 语法：有没有漏逗号 / 多逗号 / 中文引号。可以把 JSON 粘到 https://jsonlint.com 先验证。

### Q2：想测试极端数值但又怕影响孩子正常存档？
- 改 `values.storageKey` 为 `"zongmen_save_v1_debug"` 即可把调试用存档和孩子正式存档分开；试完改回原 key。
- 也可直接用 **设置 → 导出** 先把孩子进度存好再折腾，出问题 **设置 → 导入** 恢复即可。

### Q3：新增了建筑 key 但代码不认识 workerType？
- `buildings.json` 只管元数据与卡片渲染。**工位/生产逻辑**还需要在 `index.html`（对应 `kuangCap`、`assignToKuang`、`tick()` 等函数）补充相应分支，建议跟开发文档的里程碑同步新增。

### Q4：F12 控制台能临时改数值吗？
能。在控制台改：
```js
GameConfig.values.produce.basePer10s = 3;   // 下一个 tick 就按新值算
```
这是"本页面本次会话"的临时效果，刷新就失效。正式改还是写回对应 JSON。

### Q5：孩子的存档想复制到爸爸电脑/另一台浏览器上继续玩？
1. 孩子电脑：进入游戏 → 底部 **设置 → 📦 导出存档为 JSON 文件** → 得到 `宗门-存档-XX宗门-小掌门-YYYYMMDD-HHMM.json`。
2. 把文件拷到爸爸电脑（发微信/邮件/U 盘都行）。
3. 爸爸电脑：进入同一个《宗门》页面 → 底部 **设置 → 📥 从 JSON 文件导入存档** → 选刚才的文件 → 提示导入成功后自动刷新，进度无缝接续。
> 注意：两台机器如果用了不同的 `values.storageKey`，导入会写到当前浏览器当前 key 下（一般孩子和家长都用默认 `zongmen_save_v1`，无需额外调整）。

### Q6：孩子误点想"重开新档"？
- 现在提供的是**带二次确认 + 文字验证**的重置流程：底部 **设置 → 🔄 重置存档** → 会强制要求输入 `values.saveFile.confirmResetWord`（默认「重置」）两个字。
- 家长若担心孩子能认出「重置」，可把 `confirmResetWord` 改成更隐蔽的句子（如 "和爸爸一起重建宗门"），这样孩子单点点不掉。
- 正式重置前，建议先让家人都点一下 **导出** 做个备份存档，避免误操作后无回退。

### Q7：导出的 JSON 文件能不能自己用记事本改再导入？
可以。文件结构很直观：
```json
{
  "__zongmen_save__": true,
  "meta": { "_exportedAt": "ISO时间", "_storageKey": "zongmen_save_v1", "_version": "1.2" },
  "data": { /* 跟 localStorage 里一模一样的 state */ }
}
```
想把灵石改成 99999：打开 JSON → 搜 `"lingshi"` → 改 `data.resources.lingshi = 99999` → 保存 → 回到游戏 **设置 → 📥 导入** 即可。推荐改之前先复制一份，改错了导入时如果校验不通过会提示"不是有效的宗门存档"。

### Q8：孩子说「底部导航太大了、看着像游戏的按钮不像古风 App 的菜单」怎么瘦身？
直接改 `assets/config/ui.json → layoutTokens.bottombar_*` 一把：
```json
"bottombar_padding":   "3px 5px",
"bottombar_border_w":  "1.2px",
"bottombar_btn_pad":   "5px 3px",
"bottombar_btn_fs":    "11px",
"bottombar_btn_radius":"6px",
"bottombar_btn_margin":"0 2px",
"bottombar_gap":       "1px"
```
同步把顶栏也瘦身：`leader_avatar_size = "28px"`、`sect_name_size = "13px"`、`topbar_padding = "4px 10px"`。刷新立刻变精致。

### Q9：AI 画了一张新的场景背景图，想把每栋建筑卡到"山上的大殿、山脚的矿场、门口的招募堂"具体位置？
三个步骤即可：
1. **把 AI 画好的场景图作为场景背景**：图片丢到 `assets/img/scene_bg.jpg`（覆盖默认或改 `ui.json.images.sceneBg` 指向新路径）→ 决定是否"只在 #scene 画布内铺这张图"：如果你的场景图上下方画了远山和地平线（和顶栏/底栏的内容区一致更适配），就把 `ui.json.layoutTokens.scene_bg_fixed = false`。
2. **打开设置 → 🎯 建筑位置快速调参模板 → 📋 复制整块到剪贴板**。粘贴到 `assets/config/buildings.json` 的对应建筑块（或新建文件）里。
3. 改每个建筑的 `position:{x,y,w,h}`：大殿一般放在背景中轴线上方（y≈20~30）；矿场放左侧山脚（x≈20, y≈60）；招募堂放右侧入口（x≈80, y≈65）。**x/y 是卡片中心点百分比**，所以大殿居中靠上就写 `{x:50,y:28,w:24,h:38}`。保存刷新再看位置，几轮微调就能完全对齐背景图。
> 小技巧：如果大殿标签文字刚好压在背景图的山头上，可以改 `labelPosition = "top"`（让文字浮在卡片上方），或者给这座建筑单独写一条 `buildingMeta.dian.cardStyle = {"background":"rgba(255,250,220,.2)"}` 让卡片更透、更融合背景。

### Q10：建筑卡片在 flex 老模式和 positional 新模式之间，我想偶尔切着看怎么办？
改 `ui.json.layoutTokens.building_mode = "flex"` → 回到老 flex 模式（所有卡片等宽、居中一排）；改回 `"positional"` 就恢复坐标摆放。文件里的 `position` 数据不会因为切回 flex 就丢，所以可以放心来回切对比效果。

### Q11：怎么让药田产灵药更快？
两条路都可以叠加生效：① 给更多弟子分配到「药田」（大殿升 Lv.2 → 药田 Lv.2 → 工位 2，就可以放 2 个弟子一起种）；② 改 `values.json → produce.lingyaoPerMul = 2` → 灵药产量 × 2。

### Q12：想给第一个弟子突破时 100% 成功，怎么调最稳？
直接用丹药堆上去。练气→筑基基础成功率 80%，默认最多额外吃 2 颗丹药，每颗 +10% → 总共 80% + 20% = 100%。界面上点「🚀 突破筑基」→ 选"额外 +2 颗"→ 确认 → 必成功。如果想让孩子省丹药、直接不用堆就能稳过，就调 `realms.json → realms.lianqi.breakthrough.baseSuccessRate = 1`。

### Q13：今天的任务我做完领完了，想让孩子再做一轮怎么办？
两种方法任选：① 调系统日期到明天（不推荐，会影响孩子对真实时间的感知）；② 更稳的方式：F12 打开控制台执行 `state.quests.date = ""; ensureDailyQuests(); render();` → 今日任务列表会随机刷新 3 条新的（任务池总共 5 条，所以会不一样）。

## 八、开发者：ConfigLoader 的契约

`assets/config.js` 对外暴露 `window.GameConfigLoader`：

```
GameConfigLoader.loadAll()                  -> Promise<{cfg, sourceMap, warnings, usedFallback}>
GameConfigLoader.validate(cfg)              -> warnings[]（缺字段会回填默认值并收集告警）
GameConfigLoader.injectThemeColors(colors)  -> 注入 CSS 变量 --qing/--wood/--gold/--ink/--cloud
GameConfigLoader.injectLayoutTokens(tokens) -> 注入 UI 尺寸 CSS 变量 --l-*（顶栏/底栏/建筑/弹窗全部 token 化）
GameConfigLoader.helpers(cfg)               -> H：producePer10s / upgradeCost / expNeeded / discipleCap / slotCap / recruitCdSec / moraleMul / genName / maxLevel
```

业务代码（index.html 等）不应再硬编码任何常量，全部走 `GameConfig.*` 和 `H.*`。新增模块时，把新 JSON 加入 `loadAll()` 的 6 元映射表 + 新增 validate 的对应字段分支即可。
